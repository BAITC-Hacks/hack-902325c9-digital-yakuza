# prior/ — что говорит история смен тарифов

Скрипт строит таблицы и вшивает их в `agent.py` (агент во время работы файлы не читает):

```bash
cd beeline_agent
python prior/build_prior.py          # чистка + оценка + вшивка PRIOR, PRIOR_UNSEEN, PRIOR_SCORE в agent.py
python prior/evaluate_estimators.py  # сравнение способов оценки (split-half), ~10 с
python prior/similarity.py           # сходство истории и аудитории, ~5 с
```

| Словарь в `agent.py` | Что внутри |
|---|---|
| `PRIOR_FORMAT = ("q", "q_se", "n_obs")` | формат кортежей; проверка R6 тренажёра сверяет его с агентом |
| `PRIOR[(from, seg, to)] = (q, q_se, n_obs)` | 451 тройка с историей; по умолчанию `PRIOR_MODE = "raw"` — q как в моке (см. п. 5) |
| `PRIOR_UNSEEN[(from, seg, to)] = (q, q_se, 0)` | 809 троек ячеек аудитории без истории: 720 — 12 тарифов без истории, 89 — пробелы по ячейкам |
| `PRIOR_PARTS[(from, seg, to)] = (pct, conv)` | из чего сложен q (все 1 260 троек): чтобы масштабировать разброс переноса конверсией, `TRANSFER_SD_PCT × conv` — редкий переход не может дать большой эффект |
| `PRIOR_SCORE[(from, seg, to)] = (q_level, q_contrast, q_se)` | разложение q для всех 1 260 троек (см. п. 2) |

Единицы (договорённость с агентом):
- `q` — база эффекта: Δ% × доля перехода, до множителя канала, доля от ARPU абонента; эффект на канале = `q × m_c`;
- `q_se` — стандартная ошибка оценки q по истории, в единицах q; размер выборки уже учтён — агент берёт как есть,
  на √n не делит. Перенос «история → аудитория» — отдельная настройка агента `TRANSFER_SD`:
  `sd = √(q_se² + TRANSFER_SD²)`;
- `n_obs` — число наблюдений, только для справки.

Как считается `q_se` (дельта-метод для q = pct × conv):
- `PRIOR`, режим raw: `q_se = √((conv·se_pct)² + (pct·conv_se)²)`, `se_pct = pct_std/√n`, где разброс Δ% подтянут
  к разбросу сегмента (иначе при n = 2–3 случайно близкие значения дают ложную уверенность),
  `conv_se = √(conv(1−conv)/N_ячейки)`;
- режим hier: то же, но `se_pct` = апостериорная sd из иерархии (размер выборки в ней уже учтён),
  `conv_se = √(conv(1−conv)/(N + α + 1))`;
- `PRIOR_UNSEEN`: `q_se = √((conv·pct_unc)² + (pct·cv·conv)²)`, где
  `pct_unc = √(pct_sd² + (pct − pct_fallback)²)` — иерархия (в ней уже ошибка переноса контраста, LOO ≈ 0.24)
  плюс расхождение с fallback-правилом среды (0.4 × Δцены / медиана цены), а `cv ≈ 0.93` — коэффициент вариации
  доли перехода между тройками с историей (для тройки без данных долю мы по сути не знаем).

Проверка по корзинам n_obs (медиана `q_se / |q|`): 1–2 набл. — 1.46, 3–5 — 1.10, 6–20 — 0.70, 21–50 — 0.48,
50+ — 0.34; у `PRIOR_UNSEEN` — 1.98 (медиана `q_se` 0.041 против 0.029 у `PRIOR`). В абсолютных единицах
у редких переходов `q_se` мала потому, что мала доля перехода: редкий переход не может дать большой эффект.

Пилот на канале c покажет примерно `m_c·q` плюс шум `0.804/√n`. Это стартовая оценка и ранжирование, а не деньги.
Файлы: `prior_table.csv`, `prior_unseen.csv` (+ соответствие пакета), `breakeven.csv` (пороги каналов),
`reports/` (сравнение оценок, сходство, параметры).

## 2. Модель: уровень страты + контраст цели (`prior/hier.py`)

Плацебо показывает: общий сдвиг ARPU внутри страты «тариф_откуда × сегмент» — это в основном регрессия
к среднему, одинаковая для любых целей. Поэтому
`Δ%(from, seg, to) = L(from, seg) + C(from, seg, to)`:
- **L — уровень страты**: сжат к среднему сегмента (LOW +1.02, MID +0.26, HIGH −0.13). Внутри истории
  стабилен (split-half 0.87), но это дрейф, и в реальной аудитории он может быть другим.
- **C — контраст цели**: иерархический EB «цель → сегмент×цель → ячейка», сила сжатия на каждом уровне —
  методом моментов (τ = 0.18 / 0.13 / 0.14). Контраст по целям: tariff_9 +0.23, 8 +0.09, 11 +0.08,
  10 +0.07, 12 +0.01, 4 −0.03, 13 −0.14, 21 −0.18, 1 −0.61.
- Для 12 тарифов без истории C = 0 («как средняя цель страты»), sd ≈ 0.30: ранжировать их по истории нельзя,
  только пилотом.

Split-half (30 разбиений, цель — то, что считает среда), RMSE Δ%:

| Оценка | 1–5 набл. | 6–20 | 21+ | все | ранговая корр. |
|---|---:|---:|---:|---:|---:|
| **уровень + контраст (hier)** | **0.58** | 0.42 | **0.14** | **0.28** | **0.77** |
| сжатие к ценовой регрессии (прошлая версия) | 0.61 | 0.42 | 0.15 | 0.29 | 0.75 |
| простое среднее (мок) | 0.78 | 0.47 | 0.16 | 0.33 | 0.71 |
| медиана | 0.95 | 0.71 | 0.26 | 0.48 | — |

`PRIOR_SCORE` отдаёт обе части в единицах q: `q_level = L·доля`, `q_contrast = C·доля`, `q_se` — ошибка их суммы. Для «структурного»
постериора агента: `эффект ≈ a + b1·q_level + b2·q_contrast + отклонение руки`. Если b1 ≈ 0 — дрейф истории
в этой среде не переносится; b2 — насколько переносится ранжирование целей (оно надёжнее).

Доля перехода: у троек с историей — сглаженная к структуре переходов сегмента (α = 10); у троек без истории —
медианная (так делает fallback среды) × (0.5 + 0.5·fit), где fit — доля абонентов ячейки, чей трафик и минуты
помещаются в пакет тарифа (`prior/unseen.py`, метки «подходит / частично / не подходит» в `prior_unseen.csv`).

## 3. Пороги каналов (`breakeven.csv`)

Для каждой ячейки аудитории по среднему predicted_arpu (A):
- `be_<канал>` — канал окупается сам: `q > cost / (m·A)`; для tariff_8/HIGH звонок — 1.7%, SMS — 0.08%;
- `be_<канал>_vs_<дешевле>` — канал лучше предыдущего с учётом цены бюджета (1 у.е. в финале ≈ 10 у.е. прироста):
  `q > Δcost·10 / (Δm·A)`; для tariff_8/HIGH звонок против рекламы — 50%, реклама против SMS — 11.5%,
  SMS против push — 3.4%.

## 4. Похожа ли история на аудиторию (`reports/similarity.json`)

Средний ARPU 6 413 против 3 647; HIGH 59% против 30%; HEAVY 50% против 29%; медиана трафика 2 029 против
232 МБ; overlap структуры тарифов 0.55; adversarial AUC 0.69–0.73. Веса важности из adversarial-модели
оставляют ~54% эффективной выборки. В приор по умолчанию не включены: главная неопределённость — дрейф
уровня, а его перевзвешивание по признакам не исправит; это закрывают пилоты и `q_level` в постериоре.

## 5. A/B на мирах: что приор даёт агенту

Точность на истории ≠ результат агента. Текущий агент Димаша, одни и те же миры, меняется только `PRIOR`:

| Проверка | Сырой q (как мок) | Сжатие к цене (v1) | Уровень + контраст |
|---|---:|---:|---:|
| 20 «честных» миров: приор по половине A истории, истина — по непересекающейся половине B (`prior/ab_worlds.py`) | 4.21 млн (медиана) | — | 3.99 млн; разница −0.18 ± 0.23 млн, лучше в 30% миров |
| 60 миров `random` (sim) — средний / P(итог < 0) | 1.04 млн / 13% | 0.90 млн / 20% | 0.88 млн / 13% |
| 20 миров `resample` (sim; смещено в пользу сырого q — та же история) | 4.12 млн | 3.73 млн | 3.67 млн |

Разница в пределах шума, но направление везде одно: с текущей логикой агента (кандидат = q > 0, разведка по
оптимистичной оценке) сжатая оценка не помогает — у неё больше положительных q (304 против 263, в основном
малые ячейки LOW/MID, подтянутые дрейфом уровня), и 20 пилотов распыляются. Поэтому в `PRIOR` по умолчанию
оставлен сырой q (`PRIOR_MODE = "raw"`, мок снова даёт 4 377 794), а иерархическая оценка идёт в
`PRIOR_SCORE` и колонки `q_hier`, `q_level`, `q_contrast` — для структурного постериора. Переключение:
`PRIOR_MODE = "hier"` в `build_prior.py`. Решать — прогоном на мирах после изменений агента.
