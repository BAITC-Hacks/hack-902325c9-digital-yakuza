# prior/ — что говорит история смен тарифов

Таблица `PRIOR[(тариф_откуда, ARPU-сегмент, тариф_куда)] = (q, n_obs, pct_std)` вшивается в `agent.py`.
Агент во время работы файлы не читает.

```bash
cd beeline_agent
python prior/build_prior.py          # чистка + оценка + вшивка PRIOR в agent.py
python prior/evaluate_estimators.py  # сравнение способов оценки (split-half), ~10 с
python prior/similarity.py           # сходство истории и аудитории, доверие к истории, ~5 с
```

## 1. Чистка `data/change_tariff.csv`

| Что | Строк | Решение | Почему |
|---|---:|---|---|
| Полные дубли (тот же ID, те же цифры) | 6 | убраны | одна смена записана дважды — удваивала бы вес |
| ARPU до смены = 0 | 1 406 | убраны | Δ% = (после − до) / до не определён |
| ARPU до смены < 0 | 1 | убрана | то же, плюс это корректировка начислений, а не выручка |
| ARPU до смены в (0; 100) | 711 | убраны | Δ% взрывается (100 → 3 000 = +2 900%); среда (мок) считает так же, с порога 100 |
| Δ% > +300% | 843 | оставлены, обрезаны до +300% | правило среды: эффект считается по клипнутому Δ% |
| ARPU после = 0 (Δ% = −100%) | 962 | оставлены | реальный исход: абонент перестал платить после смены — это и есть риск downsell |
| Выбросы ARPU до смены (до 333 тыс.) | 15 выше p99.9 | оставлены | Δ% относительный и ограничен снизу −100%, выброс не ломает среднее; строки валидны |

Итого из 14 823 строк в расчёт идут **12 699**. Порог 100 проверен на чувствительность: средний Δ% в LOW
меняется с 1.17 (порог 1) до 1.02 (порог 100) и 0.90 (порог 500) — порог 100 совпадает с правилом среды.
В аудитории 1 188 абонентов с ARPU_3m_avg < 100, но predicted_arpu < 100 только у 140 — для них это не важно.

## 2. Какая оценка эффекта надёжнее

Историю 50 раз делили пополам по абонентам: по половине A считали оценку каждой связки,
по половине B — то, что считает среда (среднее клипнутого Δ%). RMSE оценки Δ% (меньше — лучше):

| Оценка | 1–5 набл. | 6–20 | 21+ | все |
|---|---:|---:|---:|---:|
| **среднее + сжатие к регрессии по цене (EB)** | **0.61** | **0.43** | **0.15** | **0.29** |
| EB от усечённого среднего 10% | 0.60 | 0.43 | 0.16 | 0.29 |
| среднее с винзоризацией 5–95% | 0.77 | 0.47 | 0.16 | 0.33 |
| простое среднее (было) | 0.79 | 0.48 | 0.16 | 0.34 |
| усечённое среднее 10% | 0.79 | 0.50 | 0.17 | 0.35 |
| усечённое среднее 20% | 0.82 | 0.56 | 0.20 | 0.38 |
| медиана | 0.97 | 0.73 | 0.26 | 0.49 |

- **Медиана и усечённое среднее хуже.** Среда считает эффект как среднее, а Δ% скошен: 8% переходов
  дают −100%, 7% упираются в +300%. Медиана отрезает эти хвосты и систематически ошибается.
- **Малые группы ненадёжны.** На связках с 1–5 наблюдениями ошибка простого среднего 0.79 — это больше
  самого эффекта. Сжатие (empirical Bayes) подтягивает такие связки к регрессии «Δ% ~ разница цен»
  внутри сегмента и снижает ошибку на 23%. Связки с 20+ наблюдениями почти не меняются.
- **Доля перехода** сглажена к структуре переходов сегмента (α = 10): 1 переход из 2 больше не даёт 50%.
  Ошибка q = Δ% × доля: 0.080 (было) → 0.074.
- Колонка `reliability` в `prior_table.csv`: high (20+ набл.), medium (6–19), low (1–5).

Регрессия по сегментам (Δцены — в долях медианной цены тарифа 5 935):
HIGH `Δ% ≈ −0.12 + 0.15·Δцены`, MID `+0.23 + 0.39·Δцены`, LOW `+1.02 + 0.31·Δцены`.
HIGH при переходе на тариф той же цены в среднем теряет 12% ARPU, LOW растёт почти при любой смене
(частично это регрессия к среднему: у кого ARPU был низким, у того он чаще подрастает).

## 3. Похожа ли история на аудиторию (`prior/reports/similarity.json`)

| | Аудитория | История |
|---|---:|---:|
| Средний ARPU | 6 413 | 3 647 |
| HIGH / MID / LOW | 59 / 29 / 12% | 30 / 44 / 26% |
| HEAVY / LITE / NON_USER по данным | 50 / 44 / 6% | 29 / 45 / 26% |
| Медиана трафика, МБ/мес | 2 029 | 232 |
| Совпадение структуры тарифов (overlap) | 0.55 | |

Overlap (1 = распределения совпадают): ARPU-сегмент 0.75, data-сегмент 0.82, call-сегмент 0.98, тариф 0.55.
Внутри HIGH аудитория богаче (медиана ARPU 8 111 против 6 655). 99.8% аудитории сидит в ячейках
«тариф × сегмент», по которым в истории 30+ смен, — пробел не в стартовых ячейках, а в целевых тарифах (п. 4).

**Переносимость.** Внутри истории выделили половину, похожую на аудиторию по сочетанию сегментов,
и проверили, как её q связан с q остальной половины: наклон β ≈ 1.0, корреляция 0.85, знак совпадает в 92%
(на случайном разбиении — 0.95 и 0.92). То есть различия в составе (сегменты, трафик) сами по себе
эффекты почти не сдвигают: в среднем история не завышена. Но организаторы прямо пишут, что реальные эффекты
другие, и этот сдвиг данными не измерить. Рекомендация для `agent.py`:
- `PRIOR_SHRINK`: данные не требуют 0.5; разумно **0.7–0.8** — перестраховка от сдвига без потери ранжирования;
- `PRIOR_MODEL_SD` ≈ **0.09–0.10 в единицах q** (остаточный разброс переноса) — текущее 0.10 подходит,
  если его трактовать в единицах q (см. замечание ниже).

## Формат и замечание для agent.py

Формат не менялся: `(q, n_obs, pct_std)`. `q` — сжатая оценка Δ% × сглаженная доля перехода,
`n_obs` — наблюдений после чистки, `pct_std` — внутригрупповой разброс Δ% (для малых групп подтянут
к разбросу сегмента). В `prior_table.csv` есть и старые величины (`pct_mean`, `conversion_raw`, `q_raw`).

Единицы: в `_cell_prior` `mu` — в единицах q (Δ% × доля перехода), а `pct_std²/n_obs` — в единицах Δ%.
Выборочная ошибка q примерно в `1/conversion` раз меньше (доля перехода 0.1–0.6). Если нужно — могу
отдавать третьим элементом разброс уже в единицах q (`pct_std × conversion`), формат кортежа тот же.
